# ABA PayWay Live-Source Audit → SDK + CLI Enhancement Plan (v1.4.0)

## Audit result (live source: developer.payway.com.kh, all 24 spec pages fetched 2026-08-31)

The live docs define **24 operations over 22 unique endpoint paths** (Subscription reuses the purchase path; Complete-pre-auth-with-payout reuses the pre-auth-completion path). **The SDK implements all 22 paths** — endpoint coverage is complete. The gaps are parameters, validation, error handling, and one now-solvable blocked capability:

| Live API (#) | SDK | Key gaps |
|---|---|---|
| 1 Purchase | ✅ full 24-field hash match | no name/email/phone/items/lifetime-max/google_pay_token conditional validation; sends JSON not multipart (sandbox-tolerated) |
| 2–4 Check/Close/Detail | ✅ complete | none |
| 5 Refund | ✅ | none (RSA blob + `request_time` hash correct) |
| 6 Transaction list | ✅ all 9 params | no ≤3-day window / `pagination ≤ 1000` / status-enum pre-validation |
| 7 Exchange rate | ✅ | none |
| 8 Link account | ✅ path | live requires `ctid`, `currency`, `token_flag` (SDK: all optional); token-flag enum drift (live: CITI_FLEX/CITO_FLEX); docs-vs-verified hash order conflict |
| 9 Link card | ✅ | missing `continue_success_url`; live returns HTML always (ungraceful today) |
| 10 CoF payment | ✅ path | missing 10 optional params (names/email/phone/purchase_type/items/return_params/payout/custom_fields/shipping_fee); `request_id` sent though absent from live doc; hash-order conflict |
| 11–13 Token trio | ✅ path, **gated** | live docs now publish per-endpoint HMAC compositions; SDK uses one wrong shared one (`request_time, merchant_id, request_id, ctid, pwt`); get-token-details needs only `request_id` (no ctid/pwt) |
| 14 Subscription | ❌ **params missing** | purchase needs `ctid`, `token_flag: CITR_FIX`, `frequency` (1W/1M/2M), `abapay`/`abapay_deeplink` options (R-07, live-confirmed) |
| 15 QR API | ✅ path | missing 9 optional params (items, names, email, phone, return_deeplink, custom_fields, return_params, payout); missing throttle rule & COF/QR error families |
| 16–17 Payment link | ✅ | missing `payout` + `image` (3MB, multipart) params; title ≤250 unvalidated |
| 18–20 Pre-auth | ✅ hash orders match live | `idempotency_key`/`reason` are SDK extensions (document as such) |
| 21 Payout | ✅ hex hash match | no KHR≥100 / USD≥0.01 min-amount rule |
| 22–23 Beneficiaries | ✅ | **no CLI commands** |
| 24 Get txns by merchant_ref | ✅ | `merchant_ref ≤ 20` unvalidated; missing 10/min throttle rule |

Error-handling gaps: COF `code "04"` + `errors{}` map unparsed; QR string-code family (1/6/12/16-19/21/23/32/44/47/96/102/403/429) and codes 98/104/105 unknown to `explain`; `PayWaySignatureError` defined but never thrown; link-card HTML responses ungraceful.

**Key safety invariant:** `generateHmac` pads omitted fields with `''`, and empty strings vanish in concatenation — so extending a hash list to the live full field order is **backward-compatible** for existing callers. Pin with before/after hash tests.

Adopted decisions (no user answers; recommended defaults): mixed validation (enforce documented-required fields, warn advisory limits via new `strictValidation` flag), token trio probe-then-un-gate, full CLI gateway parity.

## Implementation batches

**B0 — Audit artifact + spec refresh.** Write `audit-results/live-api-coverage-2026-08-31.md` (24-op matrix with live URLs + SDK deltas, as above). Update `payway-openapi/` (subscription params, token-trio hashes, QR 19-field list, CoF payment full set, link-card `continue_success_url`, payment-link `payout`/`image`), then `npm run bundle && npm run generate-types`. DoD: typecheck green, artifact committed.

**B1 — QR parity** (`src/domains/qr.ts`, `src/client.ts`). `GenerateQrParams` += items, firstName/lastName, email, phone, returnDeeplink, customFields, returnParams, payout; hash list extended to the live 19-field order; `lifetime` + `qr_image_template` always sent; validations: names ≤20, email ≤50 (warn), phone ≤20, items ≤500/≤10 entries, wechat/alipay USD-only warn. Hash-composition pin tests (empty-param hash must equal today's).

**B2 — CoF + subscription parity** (`src/domains/credentials-on-file.ts`, `src/domains/checkout.ts`, `src/client.ts`). LinkAccount: `ctid`/`currency`/`tokenFlag` become required (throw; CHANGELOG breaking note); keep sandbox-verified extra token flags with warn. LinkCard: += `continueSuccessUrl`. CofPayment: += the 10 optional params (body + hash positions per live order; ship behind probe outcome from B3 for hash-sensitive ones). Purchase/subscription: `CreateTransactionParams` += `ctid`, `tokenFlag` ('CITR_FIX'), `frequency` ('1W'|'1M'|'2M') + `abapay`/`abapay_deeplink` accepted; validate frequency required iff tokenFlag=CITR_FIX; hash extended in live order (append `token_flag`, `frequency` after `skip_success_page`). Stretch: opt-in multipart for purchase/link-create/link-card (config flag, default unchanged).

**B3 — Token-trio sandbox probe + un-gate.** `scripts/probe-token-trio.ts` (re-runnable, evidence → `test-output/token-trio/`): renew `ctid.request_time.pwt.merchant_id.request_id`; get-details `merchant_id.request_time.request_id` (body: request_time, merchant_id, request_id only); remove `merchant_id.ctid.request_time.pwt`. Also probe CoF-payment full live composition. If verified: split `TokenParams` into per-endpoint types, flip `allowUnverifiedTokenOperations` default to allowed (keep flag as escape hatch, deprecate), append SANDBOX-FINDINGS §15, update RTM R-04/05/06 + ABA-OPEN-QUESTIONS Q6. If not: keep gate, record attempt matrix. Sandbox-only, scoped `NODE_TLS_REJECT_UNAUTHORIZED='0'`, never production.

**B4 — Validation framework** (`src/utils.ts`, `src/client.ts`). `warnAdvisory()` one-time-warn helper + `strictValidation?: boolean` config (+ `PAYWAY_STRICT_VALIDATION` env) that escalates warns to `PayWayConfigError`. Rules: purchase names ≤100 no-digits / email ≤50 / phone ≤20 / items ≤500·≤10 / lifetime max 43200 warn; list 3-day window + pagination ≤1000 + status enum; merchant_ref ≤20; min amounts (KHR≥100, USD≥0.01) for payout/CoF payment/QR/payment-link; payment_option enum warns; google_pay_token required iff option=google_pay.

**B5 — Graceful error handling** (`src/client.ts`, `src/cli/explain-code.ts`). Parse COF family: `04`+`errors{}` → `PayWayBusinessError` with `fieldErrors`, '01'/`1`/PTL02 → throw `PayWaySignatureError` (finally used) with endpoint hash-list hint; 98 → merchant-profile hint; 104/105 → token-flag/token hints. QR string-code table. `explain` += `cof` + `qr` families. Throttle rule for get-transactions-by-mc-ref (10/60s). Link-card HTML detection → structured error/hint.

**B6 — CLI full parity** (`src/cli.ts`, `src/test/index.ts` mock server). New `cof` group: `cof link-account`, `cof link-card`, `cof charge`, `cof token renew|details|remove`; `beneficiary add|update-status`; generate-checkout += subscription trio (`--ctid --token-flag --frequency`) + pre-auth type + items/shipping/names/lifetime/custom-fields/payout/etc.; generate-qr += the 9 new params; transaction-list pre-validates 3-day window/pagination cap (exit 1 with hint). All with `--json`, registered in COMMAND_GROUPS, in-process `runCli` tests + mock-server handlers per endpoint.

**B7 — Docs & release.** CHANGELOG v1.4.0; README/AGENTS.md command examples; docs/09 (token lifecycle resolution), docs/12 (new error families); HANDOFF §5 refresh (5.4 Q6 resolved/updated, new item links to audit artifact). Release via `docs/RELEASE_CHECKLIST.md`.

## Gates & risks
- Every commit: `npx vitest run` (≥988 green, expect ~1,050+), `npx tsc --noEmit`, `npx biome lint src`. Behavior pins in `edge-case-audit.test.ts` flipped only consciously with CHANGELOG notes. Conventional commits on a feature branch (current branch has unrelated WIP — create `feat/live-api-parity` from `main` after checking it hasn't moved).
- Risks: hash-order changes gated behind probe evidence or the empty-string-padding invariant (pinned by tests); required-field enforcement is a documented breaking change (link-account callers); multipart remains opt-in; production base URL still unverified (existing open item).
