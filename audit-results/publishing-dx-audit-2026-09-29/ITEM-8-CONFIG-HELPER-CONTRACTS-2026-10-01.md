## Environment note (reusable fact)

The child-loopback constraint first documented in `starter-e2e.test.ts` is
specific to CHILD → PARENT-hosted servers (children hang; probed 5 s timeout).
CHILD → CHILD loopback TCP works on this machine (probed 2026-10-01,
`.scratch/loopback-probe/probe.mjs`), as does the fast ECONNREFUSED path to a
closed port. Process-exit-code tests that need an HTTP fixture should host the
server in a child process.
