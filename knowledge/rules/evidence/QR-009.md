# Evidence — QR-009 (documented amount floor 100 KHR / 0.01 USD)

- Rule: the transaction amount has a documented gateway floor of 100 KHR or
  0.01 USD, with a dedicated gateway response code (47).
- Source: OFFICIAL_DOCUMENTATION + OFFICIAL_API_BEHAVIOR (the gateway's own
  response-code table documents code 47 for the floor).
- URL: https://developer.payway.com.kh/qr-api-14530840e0
- Retrieved: 2026-10-05
- Expires: 2027-04-03 (retrieved + 180 days)

## What was fetched

The official PayWay developer documentation page for the QR API
(generate-qr) endpoint: the `amount` parameter description and the response
`status.code` table.

1. Initial fetch: 2026-10-05, recorded during the second-pass DX audit
   (docs/project/2026-10-05-dx-platform-audit-pass2.md, rule matrix §19.2 row
   QR-009 and finding N-01).
2. Re-verification fetch: 2026-10-05, live re-fetch of the same page for this
   evidence file. The page rendered; both quotes below were confirmed.

## Quotes (as recorded 2026-10-05)

The `amount` parameter description:

> "The total transaction amount must be at least **100 KHR** or **0.01 USD**
> and cannot be null."

The response table row dedicated to the floor:

> `47` — "KHR Amount must be greater than 100 KHR."

## Why HARD

A documented minimum with its own gateway error code is not an opinion
(audit DX-RULE-004): under-floor amounts throw `PayWayConfigError` locally,
before any network call, in normal and strict mode, citing QR-009 and the
official code 47. Before this rule the floor was advisory-only, so a
merchant could send 99 KHR and only learn about code 47 from an opaque
gateway response that the old registry described as "meaning not individually
published" (finding N-01).
