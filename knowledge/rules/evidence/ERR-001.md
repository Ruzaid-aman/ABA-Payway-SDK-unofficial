# Evidence — ERR-001 (numeric error codes are endpoint-scoped)

- Rule: the same numeric response code can carry different meanings per
  endpoint; diagnostics must resolve a code by its operation/endpoint and
  never answer with a single global family.
- Source: OFFICIAL_DOCUMENTATION (the official generate-qr response-code
  table) corroborated by the repository's sandbox-verified purchase/gateway
  code table — both as quoted in the audit.
- URL: https://developer.payway.com.kh/qr-api-14530840e0
- Retrieved: 2026-10-05
- Expires: 2027-04-03 (retrieved + 180 days)

## What was fetched

1. The official PayWay developer documentation page for the QR API
   (generate-qr) endpoint, response `status.code` table.
   - Initial fetch: 2026-10-05, recorded in the second-pass DX audit
     (docs/project/2026-10-05-dx-platform-audit-pass2.md, findings N-01 and
     N-02).
   - Re-verification fetch: 2026-10-05, live re-fetch of the same page for
     this evidence file. The page rendered and all 20 rows were confirmed

2. The purchase/gateway family meanings are NOT from a fetched official

   labelled below.

> `8` Something went wrong (contact digital support) · `12` Payment currency

> Invalid Phone Number · `19` Invalid Email · `21` End of API lifetime ·
> `23` Selected Payment Option is not enabled for this Merchant Profile ·
> `32` Service is not enable · `35` Payout Info is invalid · `44` Purchase
> amount has reached transaction limit · `47` KHR Amount must be greater than

> Invalid merchant data · `102` The URL is not in the whitelist · `403`

(The live page renders each row with full sentence text, e.g. code 16 is

more than 100 characters." and code 429 is "You've reached the maximum
attempt limit. Please try again in (min)".)

## Quote 2 — the purchase/gateway collision (reproduced, sandbox-verified)

Audit finding N-02 reproduced the unscoped resolver and computed the
collision set — numeric codes present in BOTH the `qr` and `gateway` families
with DIFFERENT titles:

> "Computed collision set — numeric codes present in **both** `qr` and
> `gateway` families with **different** titles: **1, 6, 16, 17, 23, 96**
> (6 collisions). For those codes the `gateway` meanings are respectively
> *Wrong Hash*, *tran_id not found*, ***Invalid Amount***, ***Invalid
> Currency***, *Transaction Not Found*, *Payee / Merchant Data*."

The decisive example: code 16 is "Invalid First Name" on generate-qr
(official, Quote 1) but "Invalid Amount" on the purchase gateway family
(sandbox-verified registry, Quote 2). A developer whose purchase failed with
code 16 who runs the unscoped bare lookup receives a QR-family answer about
first names — correct data, wrong key, no selector.

## Consequence encoded

Diagnostics resolve codes by operation/endpoint (`explain --operation` /
`--family`); a bare ambiguous lookup returns `ambiguous: true` with the
per-endpoint alternatives instead of silently picking the qr family. The
endpoint-scoped knowledge recorded here is what makes error resolution
operation-correct rather than accidentally-correct.

## Enforcement

- `src/cli/explain-code.ts` — `explainPayWayCodeScoped` (scoped resolution
  with `ambiguous`/`alternatives`) and `explainCodeFamilies` (all families
  claiming a code).
