# Evidence — PUR-003 (purchase `payment_option` official value set)

- Rule: purchase `payment_option` is one of exactly six officially documented
  values (`cards`, `abapay_khqr`, `abapay_khqr_deeplink`, `alipay`, `wechat`,
  `google_pay`) and is optional — omitting it lets the profile decide.
- Source: OFFICIAL_DOCUMENTATION
- URL: https://developer.payway.com.kh/purchase-14530820e0
- Retrieved: 2026-10-05
- Expires: 2027-04-03 (retrieved + 180 days)

## What was fetched

The official PayWay developer documentation page for the Purchase endpoint
(Ecommerce Checkout / Create Transaction), full parameter table.

1. Initial fetch: 2026-10-05, recorded during the second-pass DX audit
   (docs/project/2026-10-05-dx-platform-audit-pass2.md, finding P0-02 and
   rule matrix §19.2 row PUR-003).
2. Re-verification fetch: 2026-10-05, live re-fetch of the same page for this
   evidence file. The page rendered and the parameter table was readable.
   Result: the same six `payment_option` values are listed and the
   profile-default sentence is present.

## Quotes (as recorded 2026-10-05)

The `payment_option` parameter (optional, max length 20 chars):

> "`cards`: For card payments. `abapay_khqr`: QR payment that can be scanned
> and paid using ABA PAY and other KHQR member banks. `abapay_khqr_deeplink`:
> … `alipay` … `wechat` … `google_pay` … If no value is provided, the payment
> gateway will automatically display the supported payment options based on
> your profile."

(The ellipses are exactly as compressed in the audit's recorded fetch; the
2026-10-05 re-verification confirmed the full six-value list
`cards`, `abapay_khqr`, `abapay_khqr_deeplink`, `alipay`, `wechat`,
`google_pay` and the closing "If no value is provided … based on your
profile" sentence verbatim.)

Key negatives confirmed by both fetches:

- `abapay` does NOT appear on the official page.
- `abapay_deeplink` does NOT appear on the official page.

The two values come from the archived gateway spec
(`docs/archive/Default module.openapi.json`) and are carried in code as
`PURCHASE_PAYMENT_OPTIONS_LEGACY` — advised about, never rejected (risk R-A:
profile enablement is the gateway's decision, official response code 23
"Selected Payment Option is not enabled for this Merchant Profile", quoted in
the generate-qr response table at evidence/ERR-001.md).

## Enforcement

- `src/constants.ts` — `PURCHASE_PAYMENT_OPTIONS` (official 6) and
  `PURCHASE_PAYMENT_OPTIONS_LEGACY` (advisory-only archived-spec values).
- `src/domains/checkout.ts` — `createCheckoutDomain` throws
  `PayWayConfigError` citing PUR-003 for values in neither set; legacy values
  produce a non-escalating advisory (never escalated under strictValidation).
