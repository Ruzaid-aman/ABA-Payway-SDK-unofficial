# Evidence — QR-016 (`items` official cap and semantics)

- Rule: `items` supports up to 50 line items; on generate-qr the encoded
  field additionally carries a <= 500 character cap; item price/quantity are
  description-only and are NOT used for calculation or validation.
- Source: OFFICIAL_DOCUMENTATION
- URL: https://developer.payway.com.kh/qr-api-14530840e0 (generate-qr; the
  same wording appears on the purchase page,
  https://developer.payway.com.kh/purchase-14530820e0)
- Retrieved: 2026-10-05
- Expires: 2027-04-03 (retrieved + 180 days)

## What was fetched

The official PayWay developer documentation pages for the QR API

1. Initial fetch: 2026-10-05, recorded during the second-pass DX audit

## Quotes (as recorded 2026-10-05)

`items` parameter description (identical wording on both pages):

> "A Base64-encoded JSON array describing the items being purchased. It
> supports up to 50 line items with no character limit. Note: This is only
> description/remark. The price or quantity in this info will not be used for
> calculation or any validation purposes."

On generate-qr the parameter table additionally carries a field-level cap:

> "<= 500 characters"

## Semantics record (per the rule)

- The 50-item cap is a real ceiling (advisory above it in the SDK; the
  gateway may reject above it).
- The 500-character cap is generate-qr-only (field-level).
- Line items are never an amount check: no consumer may derive, validate, or
  sum an amount from item price/quantity — the official text above forbids it
  by construction.

## Enforcement

- `src/domains/qr.ts` — `createQrDomain` (generate-qr path) advises above 50

- `src/domains/checkout.ts` — `createCheckoutDomain` (purchase path) advises
