# Evidence — QR-012 (generate-qr `payment_option` official value set)

- Rule: generate-qr `payment_option` accepts exactly three officially
  documented values — `abapay_khqr`, `wechat` (USD only), `alipay`
  (USD only).
- Source: OFFICIAL_DOCUMENTATION
- URL: https://developer.payway.com.kh/qr-api-14530840e0
- Retrieved: 2026-10-05
- Expires: 2027-04-03 (retrieved + 180 days)

## What was fetched

The official PayWay developer documentation page for the QR API
(generate-qr) endpoint, full parameter table.

1. Initial fetch: 2026-10-05, recorded during the second-pass DX audit
   (docs/project/2026-10-05-dx-platform-audit-pass2.md, rule matrix §19.2 row
   QR-012 and finding P2-04, upgraded to P1).
2. Re-verification fetch: 2026-10-05, live re-fetch of the same page for this

## Quotes (as recorded 2026-10-05)

The `payment_option` parameter description:

> "Supported payment options:
> - `abapay_khqr` : Payway will response ABA KHQR.
> - `wechat` : PayWay will respond with a WeChat QR (only for USD transactions).
> - `alipay` : PayWay will respond with an Alipay QR (only for USD transactions)."

The official page marks `payment_option` required (audit N-17 groups it with
`currency`, `qr_image_template`, `lifetime` as required-on-generate-qr). The
SDK still defaults an omitted value to `abapay_khqr` pending the
requiredness probe; the default, not the requirement, is the encoded
behaviour.

Key negatives confirmed:

- `cards` is NOT documented for generate-qr (it is purchase-only).
- `abapay_khqr_deeplink` is NOT documented for generate-qr.
- `abapay` / `abapay_deeplink` (archived-spec values) are NOT documented.

Profile enablement is the gateway's decision — official response code 23
"Selected Payment Option is not enabled for this Merchant Profile" (quoted in
evidence/ERR-001.md) — so the SDK performs no local enablement check. The
Soundbox endpoint (request-qr) keeps its own spec-derived superset
(`REQUEST_QR_PAYMENT_OPTIONS` in `src/domains/qr.ts`) and is out of scope for
this rule.

## Enforcement

- `src/constants.ts` — `QR_PAYMENT_OPTIONS` (official 3).
- `src/domains/qr.ts` — `createQrDomain` (generate-qr path) throws
  `PayWayConfigError` citing QR-012 for any value outside the official set,
  in normal and strict mode.
